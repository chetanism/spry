Knowledge and size

An agent is only as good as what it reads before it starts. spry keeps what your project has learned in small, findable files, and puts hard limits on the ones an agent reads every time.

What gets recorded

KindLives inHolds
Decisionsknowledge/decisions/, one file each (D-1, …)The context, the decision, the options rejected and why, the consequences. Superseding one makes a new decision; the old one is marked superseded by D-n.
Conventionsknowledge/conventions/, one file per area of codeRules about how code is written here that the code doesn't make obvious — one per bullet, each with its why.
External behaviourknowledge/external/<service>/, one file per behaviourWhat was observed, when, the evidence, the source (documented or observed), confidence, and which items it affects. Observed wins when the two disagree.
Interview outputssecurity.md, performance.md, constraints.md, people and rolesNumbered rules — SEC-1, PERF-1 — from the setup interview, each in its own file.
Glossaryknowledge/glossary.mdOne term per concept, and the words not to use. One term per concept →

Why external behaviour gets its own place: a service's documentation says one thing and the service does another — a rate limit lower than documented, a field that is sometimes missing. Someone spends a day finding that out. Written down with its evidence, the next agent doesn't spend the day again. /spry:record writes any of these. Record what you learn →

Line budgets

Each file type has a budget in configuration, and spry check enforces it. The defaults:

FileBudget
AGENTS.md150 lines
Any knowledge item120 lines
A plan item's README.md150 lines
A slice file200 lines
Any INDEX.md entryone line

Why budgets: files grow from every slice, record and interview, and nothing else takes lines out. Without a limit, the always-read file becomes the never-read file. When a file goes over, /spry:compact moves whole sections to the files that own them, leaving a one-line pointer and losing no fact. It moves text; it never decides a rule is wrong.

AGENTS.md and its admission test

AGENTS.md is read on every task, so every line costs on every task. The admission test is written at its top:

A line stays only if it is a pointer (where something lives), a rule an agent breaks by default, or a rule that cannot be checked by a tool.

The question to ask of each line: would an agent write the wrong code without it, on a task that never opens the file it came from? A rule that passes — "Never compute a due date from the loan date — read loans.due_on (D-1)" — stays. Everything else lives in spry/knowledge/ and is linked from an index. CLAUDE.md is a single line, @AGENTS.md, so Claude Code reads the same file.

Index, then item

Conventions, decisions, external behaviour, security notes and audit reports are each an INDEX.md plus one file per item. The index is generated from each item's title and summary. An agent reads the index — one line per item — and opens only the one it needs.

That is why a summary must say the fact itself. From the Shelf example: "Open Library — lookups are rate-limited without a User-Agent: about 100 lookups per 5 minutes, then HTTP 429" is useful in an index; "Rate limit notes" is not.

Search

spry find <query> searches spry/ and AGENTS.md and lists the best sections first. It uses SQLite's full-text search (FTS5), through the standard library's sqlite3, with one row per section — document title, heading, body — leaving out link targets and generated blocks. The index lives in .spry/index.db and refreshes per file when it changes. Where FTS5 isn't available it falls back to plain search. Writ's slice summaries, kept in an adopted project's history, are listed last.

Why: agents are told to search before they plan or code. Search that returns the right section, not the right 900-line file, is what makes that habit cheap.
