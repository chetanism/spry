Installation

Two commands put spry into Claude Code; one more starts it in your project. Other agents get the same skills from a clone of the repository. Nothing is hosted — everything ends up as files in your repository.

What you need

NeedsWhy
Python 3.10 or newerThe spry tool is a single Python file using only the standard library — nothing to pip install.
gitEvery slice is a branch; the plan is versioned with the code.
A GitHub repository and the GitHub CLI (gh), signed inSkills open draft pull requests, read check results, post review comments and merge through gh. CI runs on GitHub Actions.
An agentClaude Code by default; Cursor, Gemini, Codex or any agent that reads AGENTS.md also work.
Your own test toolingspry calls your test runner, formatter, linter and type checker — it does not replace them.

Claude Code

Add the marketplace, install the plugin, then open your project and run setup:

$ claude plugin marketplace add chetanism/spry
$ claude plugin install spry@spry
$ cd ~/projects/your-project && claude

Then, inside Claude Code, pick one:

/spry:init     # a new project
/spry:adopt    # code that already exists

Both are interviews. They are covered step by step in Set up a new project and Adopt an existing codebase.

Other agents

Clone the spry repository anywhere you will keep it — the installed skills point at that folder — then run its tool from inside your project with the agent you use:

$ git clone https://github.com/chetanism/spry ~/tools/spry
$ cd ~/projects/your-project
$ python3 ~/tools/spry/plugins/spry/tool/spry.py install --agent generic
--agentWritesForThen type
genericthe skills into spry/skills/, listed in a generated block of AGENTS.mdany agent that reads AGENTS.md — Codex among them/spry:init — the agent finds it in AGENTS.md
claudeproject skills in .claude/skills/spry-*Claude Code without the plugin/spry-init
cursorcommands in .cursor/commands/spry-*.mdCursor/spry-init
geminicommands in .gemini/commands/spry/*.tomlGemini CLI/spry:init

Then start setup with init (a new project) or adopt (existing code), as above. Teammates can mix agents on one project: the rules and the tool are copied into the project, so every agent reads the same ones. Use another agent →

What setup writes

Setup copies spry's rules and tool into your project, then writes the rest from your answers. All of it is plain files you commit:

AGENTS.md                  # always read by agents; kept short
CLAUDE.md                  # one line: @AGENTS.md
.github/workflows/spry.yml # CI: check, fast checks, tests
.github/CODEOWNERS         # who reviews what (teams only)
spry/
  README.md                # start here — for humans
  spry.config.json         # levels, IDs, team, test commands
  BACKLOG.md  COVERAGE.md  DONE.md   # generated progress pages
  plan/                    # the roadmap, then one folder per item
  knowledge/               # glossary, security, performance, decisions…
  process/                 # the rules every agent follows (copied in)
  tool/spry.py             # the tool (copied in)
.spry/                     # local only, gitignored: search index, caches
  • Copied in, not linked. spry/process/ and spry/tool/ live in your repository, so CI runs without any agent, and every teammate reads the same rules.
  • Kept out of your build. Setup adds spry/ to .dockerignore or your stack's build ignore, so none of it ships.
  • Resumable. Setup writes spry/README.md last. If it stops part-way, run it again and it continues from the first unanswered topic.

The layout is explained in The plan is a folder tree.

Optional: fresh pages on every pull

The committed progress pages show the main branch as of CI's last run. To see them for the branch you are on, each person can run this once per clone:

$ python3 spry/tool/spry.py hooks

After a checkout or pull that changed the plan or a test, it refreshes the backlog, coverage and done pages into .spry/view/, which is never committed.

Optional: browse the plan in a browser

GitHub shows every page with nothing to install. On a big plan, a local view is quicker to move around in:

$ python3 spry/tool/spry.py serve

It opens the plan tree, every document and the progress pages for your working tree in your browser, with search. It is read-only and only this machine can reach it; Ctrl-C stops it. More.

Keeping spry current

spry changes often. To take what it gained since you set up, run:

/spry:update

It updates the installed plugin first, then reads spry's changelog from where your project last left off and offers each change one at a time — take it, take it adapted, or skip it. Changes you made to your own process are kept. Nothing is rewritten without a yes. Keep spry yours →

After an update in Claude Code

Run /reload-plugins once the update is done, so every skill runs the new copy.
