Use another agent

spry is built for Claude Code, but nothing about it depends on one agent. The rules live in files, the state lives in files, and the checks run in a plain Python tool. Teammates on Cursor, Gemini CLI, Codex or anything that reads AGENTS.md run the same process.

Why it works anywhere

  • Skills are thin. Each one is a short entry point that names a process file. The real logic is in the process files, the templates and the tool.
  • The process and the tool are copied into your project (spry/process/, spry/tool/spry.py), so every agent reads the same rules and CI runs without any agent.
  • State is never in a session. The plan, the work order, the claim, the falsify results — all in files and git. Switch agent mid-slice and nothing is lost.

Install the skills for your agent

Clone spry once, then run its tool from your project folder with your agent's name:

$ git clone https://github.com/chetanism/spry ~/spry
$ cd ~/projects/your-project
$ python3 ~/spry/plugins/spry/tool/spry.py install --agent generic
--agentWritesYou type
genericEach skill to spry/skills/<name>.md, and a list of them in a generated block of AGENTS.md/spry:story — the agent reads AGENTS.md, finds the skill and follows it
claudeProject skills in .claude/skills/spry-<name>/ — for Claude Code users not using the plugin/spry-story
cursorCommands in .cursor/commands/spry-<name>.md/spry-story
geminiCommands in .gemini/commands/spry/<name>.toml/spry:story

generic is the one to reach for when your agent isn't listed: most agents, Codex among them, read AGENTS.md at the start of every task.

Skills that need spry itself

init, adopt, update and contribute work with spry's own copy, not your project's. The installed versions point at the spry clone whose tool you ran (~/spry/plugins/spry above) — so keep that clone where it is, and git pull it to get newer versions.

Mixed teams

One person on Claude Code with the plugin, another on Cursor, a third on Gemini — all fine. Each person runs install for their own agent, or the project commits the generic listing once and everyone's agent reads AGENTS.md (init, adopt, update and contribute in that listing point at the installer's own clone; anyone running them should run install themselves). They all read spry/process/ and run spry/tool/spry.py, so the work order one writes is the work order the next one builds from.

What differs between agents

  • Fresh-eyes reviews need a new agent. In Claude Code that's a sub-agent started for the review. An agent that can't start one asks you to run /spry:review in a new session — see Reviews with fresh eyes.
  • Slash-command names differ slightly, as in the table above.
  • Agent hooks are Claude Code's. With the plugin, six hooks say at the moment of a mistake what the checks would say later — see Agent hooks. Other agents meet the same rules later, from spry check, merge-check and CI.
  • Nothing else. The tool, the checks, CI and the files are the same.
