Tool commands

spry.py is one Python file — standard library only, Python 3.10 or newer — copied into every project at spry/tool/spry.py. The skills call it; CI calls it; you can call it too. This page lists every command.

You rarely type these yourself

The skills run the right command at the right moment. This page is for when you want to see what a skill is doing, run a check by hand, or wire spry into CI.

Running it

$ python3 spry/tool/spry.py <command> [options]
$ python3 spry/tool/spry.py --help            # every command
$ python3 spry/tool/spry.py gate --help       # one command's flags
$ python3 spry/tool/spry.py --version
Global optionDoes
--root ROOTThe project root. Default: the nearest folder holding spry/spry.config.json, so it works from any subfolder.
--versionPrints the tool's version.

A few commands — vendor and install — are run from the plugin's copy, because they copy spry into a project. Everything else runs from the project's copy.

Checking

check

The consistency of the plan, the knowledge and the links. This is the command that turns spry's written rules into rules that are actually enforced.

spry check [--base BASE]
  • Always: front-matter, IDs, each item's place in the folder tree, the glossary's banned words, line budgets, links, references to acceptance criteria, QA scenarios, conflict checks present and resolved before ready / open, guide comments and placeholders left in finished documents, blocked_by pointing at a dropped item or forming a circle; a warning at a path over 200 characters, which Windows without long paths cannot open from most folders.
  • --base BASE — the git ref the branch merges into. Adds: a warning when a criterion's text changed under a test, a QA scenario or a check-log row that relied on it; a refusal when the branch changed a generated block; and an ID the branch and the base both took. CI passes it on pull requests.

gate

The one command that says "this code is good to go": spry check, then the fast checks (format, lint, types — cheapest first), then the affected tests, stopping at the first failure.

spry gate [--force] [--fast]
  • A pass is stamped in .spry/green against a fingerprint of the code. While the code matches, the gate runs check alone — so fixing a document after the tests passed never re-runs the tests.
  • It also runs check alone when the branch changed only documents since its merge base with the main branch.
  • With tests.retry set, affected tests that fail on a timeout run once more with no parallelism. A real failure fails both runs.
  • --fast — check and the fast checks only, no tests; stamps nothing. Used for each change while building.
  • --force — run everything even if the code is unchanged.

More: The gate and test speed.

changed

For CI: prints code=true when any file outside checks.docs changed since --base, else code=false. CI skips the fast checks and tests when it is false; /spry:merge uses it to decide whether the main branch needs re-testing.

spry changed --base BASE

merge-check

Is a closed slice ready to merge? Exits 1 if anything blocks it.

spry merge-check [--base BASE] slice

It blocks (✗) when the slice is not closed or has no closed: date or PR number, when a control the diff adds has no falsify row, when a survivor has no reason, when the branch changed a criterion and code together without criteria_approved_by: the story's owner, or when check is not clean. It warns (!) about things a person must accept at the merge — a survivor or skipped control with a reason, a covered criterion no test cites (QA checks it by hand after the merge), or one whose latest manual check failed.

review-check

Would GitHub take this review as it stands? Exits 1 if not.

spry review-check --diff DIFF [--own] payload
  • payload — the review's JSON: commit_id, event, body, comments.
  • --diff DIFF — the PR's diff (gh pr diff <n>), or - for stdin.
  • --own — the reviewer wrote the PR, so only COMMENT is allowed.

It checks every comment is anchored on lines the diff shows, every suggestion is closed, none overlap, none is a no-op.

Progress

status

Done versus total at every level, grouped by parent: milestones, epics, features, stories, slices.

spry status [--level LEVEL] [--all] [id]
  • A plan over 100 lines prints only the levels that fit and says how to go deeper.
  • id — only this item's branch of the plan.
  • --level LEVEL — stop at this level, for example feature.
  • --all — every level, however long.

coverage

Done, in progress and defined for the whole plan and for each milestone, criteria proven, slices, tasks and bugs — and what is built but not proven. Prints the coverage page on any branch.

spry coverage

backlog

What is being built, what to build next, and what stands in the way: In progress, Ready to build, Needs slicing, Blocked and Needs planning, in plan order.

spry backlog

done

Finished stories, tasks and bugs, newest first, with the day each closed (from the slices' closed: dates — never from git).

spry done

index

Regenerates the marker blocks (children tables, proof tables, coverage, backlog, done) and every INDEX.md. Run by CI on the main branch only.

spry index [--check | --restore BASE]
  • --check — change nothing; exit 1 if anything is stale.
  • --restore BASE — on a branch: put back BASE's copy of every generated block the branch changed.

view

Writes the backlog, coverage and done pages for this working tree to .spry/view/ (gitignored) — fresh pages on a branch without touching the committed ones.

spry view [--since SINCE]

--since SINCE — only when the plan or a test changed since this commit (used by the git hooks).

serve

Browses the plan, knowledge and generated pages in a browser — read-only, on this machine only. Each document is rendered with its generated blocks built for the working tree, beside the plan tree; search is find. Ctrl-C stops it.

spry serve [--port PORT] [--no-open]
  • --port PORT — default: the first free one from 8765.
  • --no-open — do not open a browser.

hooks

Installs git hooks, per clone, that refresh .spry/view/ after a checkout or pull that changed the plan or a test.

spry hooks [--remove]

Creating and linking items

new

Creates items from their templates, with the next IDs, in the right folders — one, several, or a batch of mixed types. All are written, or none.

spry new [--parent PARENT] --title TITLE [--title TITLE …] [--owner OWNER] [--dependency DEPENDENCY] type
spry new --batch FILE
  • Item types, with IDs: milestone, epic, feature, story, slice, task, bug, decision.
  • Documents without an ID of their own: checks (a story's QA file; --parent is the story), convention, external (--dependency names the service), audit.
  • Repeat --title for several items of one type under one parent; they are numbered in the order given.
  • --batch reads a JSON list of {"type", "title", "parent", "owner", "key"} from a file, or stdin with -. A parent names an item in the plan or the key of an earlier entry, so a feature and its stories go in one call.
  • With mint: main, the IDs are taken on the main branch in one commit and one push, then merged into the current branch, so two sessions never take one number. Nothing is checked out.
$ python3 spry/tool/spry.py new story --parent F-1 --title "Loan limit" --title "Overdue block" --owner Asha
$ echo '[{"key": "f", "type": "feature", "parent": "E-2", "title": "Renewals"},
        {"type": "story", "parent": "f", "title": "Renew a loan"}]' | python3 spry/tool/spry.py new --batch -

next

The next free ID for a type.

spry next type

claim

Takes a slice before opening it, then cuts its branch sl-<n>-<slug>. With mint: main the claim is made on the main branch and refused when someone already holds it.

spry claim [--owner OWNER] [--no-switch] slice
  • --owner OWNER — who is building it, from team.members.
  • --no-switch — make the branch without switching to it, for a separate worktree.

release

Gives back a claimed slice nobody is building: planned again, branch: cleared. The branch itself is left for its owner to delete.

spry release slice

link

Sets a slice's branch, pr or issue in its front-matter.

spry link [--branch BRANCH] [--pr PR] [--issue ISSUE] slice

related

Conflict-check candidates for a document: its parent, siblings, items sharing glossary terms, full-text hits on its key phrases, the files in always_check, decisions that name it — and for a slice, every open slice and the files its plan touches.

spry related file

Pull requests and issues

pr-body

A slice's pull request body: For the reviewer first (covered criteria in words, criteria changed, falsify gaps, manual checks due), then the work order and close summary. The PR body is always copied from the slice file, never edited by hand.

spry pr-body [--base BASE] slice

--base BASE — the ref the PR merges into, to show criteria the branch changed.

issue-body

A slice's GitHub issue (with slices.issue on): the work order as agreed, saying it is never updated — or, with --close, the close summary for a comment on it.

spry issue-body [--close] slice

merge-message

The squash commit for a slice: subject, summary, and the Slice:, Parent: and Covers: trailers.

spry merge-message [--ci-local REASON] slice

--ci-local REASON — CI never ran, for this reason; the gate stood in for it. Adds a CI: trailer.

Falsify

Proves a slice's tests notice its safeguards. Background: Falsify.

falsify suggest

Drafts a plan from the source lines the branch added: one candidate per guard, comparison or error line, each with a mutation that removes it, and expect taken from the slice's covers (or the bug, for a bug's slice). With no guard added, it offers up to five lines that compute or store something. With no source line added, there is nothing to falsify.

spry falsify suggest [--base BASE] [--out OUT] slice
  • --base BASE — the branch to diff against (default: main_branch).
  • --out OUT — where to write the plan (default: .spry/falsify/<slice>.json).

falsify run

Removes each control in turn, runs only the tests that should notice, and restores every file — including on an error, Ctrl-C or SIGTERM.

spry falsify run [--dry-run] [--record SLICE] [--replace] [--jobs JOBS] plan
  • --dry-run — validate the plan and list what would run.
  • --record SLICE — write the results into the slice's Falsify table; rows for controls not run stay.
  • --replace — with --record: drop the rows this run did not write.
  • --jobs JOBS — worktrees to run in parallel (default: falsify.parallel; 1 = serial).
$ python3 spry/tool/spry.py falsify suggest SL-2
$ python3 spry/tool/spry.py falsify run .spry/falsify/SL-2.json --dry-run
$ python3 spry/tool/spry.py falsify run .spry/falsify/SL-2.json --record SL-2

Knowledge and search

find

Full-text search over spry/ and AGENTS.md, best sections first. Uses SQLite's full-text search (FTS5), through the standard library's sqlite3, kept in .spry/index.db and refreshed per file; falls back to plain search without FTS5.

spry find [--limit LIMIT] [--rebuild] query [query ...]

--rebuild — rebuild the local index from scratch.

scrub

Lists private words still in a file meant to leave the project: the product name, team names and handles, glossary terms, emails and URLs. Used by /spry:contribute.

spry scrub file

Setting up

vendor

Copies process/ and the tool into a project, at spry/process/ and spry/tool/. Run the plugin's copy.

spry vendor [--force] [--root VENDOR_ROOT] [--diff]
  • --diff — change nothing; list what differs from the plugin.
  • --force — overwrite an existing spry/process/.
  • --root — the project to copy into (default: the current folder).

install

Puts the skills where another agent finds them. Run the plugin's copy.

spry install --agent {generic,claude,cursor,gemini} [--root INSTALL_ROOT]
AgentWrites
genericThe skills to spry/skills/, listed in a generated block of AGENTS.md — any agent that reads AGENTS.md can run them.
claudeProject skills in .claude/skills/spry-*, for people not using the plugin.
cursor.cursor/commands/spry-*.md.
gemini.gemini/commands/spry/*.toml, run as /spry:<name>.

codeowners

Writes .github/CODEOWNERS from team.review in the config.

spry codeowners [--check]

--check — change nothing; exit 1 if it is stale.

Testing helpers

tests

Test-suite reports from JUnit XML.

spry tests --slowest [--junit JUNIT] [--limit LIMIT]
  • --slowest — the slowest tests and files.
  • --junit JUNIT — a report file, folder or glob (default: tests.junit).

draw

A replayable choice for an exploratory walk (/spry:explore): the same seed and counter always give the same answer.

spry draw (--seed | --pick | --sample K | --shuffle | --int N) [seed] [counter]
  • --seed — print a fresh seed.
  • --pick — one line from stdin. --sample K — K distinct lines. --shuffle — every line, reordered.
  • --int N — a number from 0 to N−1.
  • counter — the step number; add 1 on every draw.

In CI

The workflow init writes runs the tool in the same order as the gate — cheapest first, and tests only when code changed:

  1. check — with --base origin/<main> on pull requests — then changed, which prints code=true|false.
  2. The fast checks, one step each — only when code is true.
  3. On a pull request: the affected tests. On a push to the main branch: every test. Nightly: every test.
  4. On the main branch: index refreshes the generated pages and commits them with [skip ci].

A change to documents alone runs check and nothing else.
