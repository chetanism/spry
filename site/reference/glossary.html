Glossary

spry uses a small set of words, each for one thing. Here they are, alphabetically, each with where to read more. Your project gets its own glossary too — for your product's words — and spry checks you stick to it.

A–C

Acceptance criterion (AC)
One behaviour of a story that a person using the product can observe, written as Given / When / Then and numbered AC-1, AC-2 … within the story. Cited as S-1/AC-2. Criteria live only in stories; numbers are never reused. Write acceptance criteria.
Adopt
Setting spry up around code that already exists, with /spry:adopt. The code is surveyed first, and nothing existing can fail spry's checks. Adopt an existing codebase.
Affected tests
The tests a change could affect, found by the test runner (vitest --changed, pytest --testmon). The gate runs these, never the whole suite. The gate and test speed.
AGENTS.md
The file every agent reads on every task. It has a hard line budget and an admission test: a line stays only if it is a pointer, a rule an agent breaks by default, or a rule no tool can check. Knowledge and size.
Always check
Knowledge files every conflict check reads, whatever the document — by default security, performance and the decisions index. Configuration.
Audience
How technical a document is, from 1 (no technical knowledge) to 10 (an engineer in this codebase). Every template declares one, and it sets the tone of the conversation while a skill works on that document. Written for its reader.
Backlog
The generated page spry/BACKLOG.md: what is in progress, ready to build, needing slicing, blocked, or needing planning — in plan order, never a hand-kept priority list. Generated pages.
Baseline (falsify)
One run of a control group's tests with nothing removed, before any mutation. A red or timed-out baseline makes the group unreliable — the tests could not have told you anything. Falsify.
Baseline (update)
spry_baseline in the config: the last changelog entry the project considered. /spry:update offers what came after. Keep spry yours.
Blocked by
The blocked_by list in an item's front-matter: what must be done first. An item waits on what it and everything above it name. check refuses a dropped blocker or a circle. The plan is a folder tree.
Bug
Something not working as the plan says, recorded under the feature or story it breaks (B-1). It does not count toward progress, but a bug that QA saw breaks a criterion un-proves it. Bugs and tasks.
Caught
A falsify result: with the safeguard removed, a test that should notice failed. This is what you want. Falsify.
Check log
The table at the bottom of a story's checks.md where QA appends one row per criterion per run: date, criterion, build, who, pass or fail. The latest row for a criterion decides it. Checks for QA.
Checks file
A story's checks.md: the scenarios QA follows by hand, and the check log. Checks for QA.
CI
Continuous integration: the checks GitHub runs by itself on every push and pull request. spry's CI runs check, then fast checks and tests when code changed, and on the main branch writes the progress tables. The gate and test speed.
Claim
Taking a slice before opening it (spry claim), so nobody else starts the same one. The claim is the slice's branch: being set while it is still planned. Work as a team.
Close summary
The second part of a slice file, written at /spry:slice-close: what changed from the plan and why, the falsify table, and follow-ups. Close and merge a slice.
Conflict check
Before a document goes ready or a slice goes open, the agent reads everything it could clash with and records each finding and how it was resolved, in the document. check refuses one that is missing or still has a finding marked open. The conflict check.
Conflict kinds
Duplicate — another item already says this. Overlap — part of it is covered elsewhere. Contradiction — it says the opposite of an item, decision or rule. Dependency — it needs another item first. Scope — it is outside its parent's scope. Term — a word clashes with the glossary. Collision — a slice touches the same files as an open slice. The conflict check.
Control
One safeguard a slice added — a guard, a validation, a permission check, an error branch — that falsify removes to see whether a test notices. Falsify.
Convention
A rule about how code is written in this project that the code itself does not make obvious, kept in spry/knowledge/conventions/. Record what you learn.
Coverage
The generated page spry/COVERAGE.md: done, in progress and defined at each level, criteria proven, and what is built but not proven. Generated pages.
Covers
The criteria a slice builds, in its front-matter (covers: [AC-1, AC-2]). A story's slices between them cover all its criteria. Split a story into slices.
Criteria approved by
A line in a slice, criteria_approved_by: <name>, that only the story's owner's yes puts there. Without it, merge-check blocks a branch that changes a criterion and code together. Where a person decides.

D–F

Decision
A choice between options that someone will later ask about: context, the decision, the options rejected and why, consequences. One file each, D-1, D-2 …. Record what you learn.
Demo
The part of a work order that shows the slice working: copy-pasteable commands with no value to fill in by hand. Every slice demos one visible change. Build a slice.
Derived
Worked out by the tool from the files, never typed by a person. Progress, done, the backlog's order and the relationship map are all derived. Status is derived.
Diff
The lines a change adds and removes. spry reads a slice's diff to write What changed and to decide which safeguards falsify must break. Falsify.
Done
Never written — derived. A slice is done when closed (and so merged). A story is done when all its slices are done and every criterion is proven. A feature, epic or milestone is done when all its counted children are. Status is derived.
Done page
The generated page spry/DONE.md: every finished story, task and bug, newest first, dated by the day its last slice closed. Generated pages.
Draft
The state of a plan item still being written. It becomes ready on a person's yes, after its conflict check. The plan is a folder tree.
Draft pull request
A pull request marked not ready to merge. slice-open opens one with the work order as its body; slice-close marks it ready at the end. Build a slice.
Dropped
The state of an item that will not be done. It no longer counts toward its parent, and nothing may be blocked by it.
Epic
A body of work under a milestone (E-1): why, who it is for, done-when, scope. Optional — a small project can drop the level. Plan the work.
Explore
Exploratory testing by an agent with /spry:explore: a seeded, replayable random walk over an isolated instance, each step predicted from the criteria before it runs. Report only. Test beyond the slice.
External behaviour
A fact about how a service you depend on actually behaves — observed or documented, with evidence — in spry/knowledge/external/<service>/. Record what you learn.
Falsify
Proving a slice's tests notice its safeguards: each control is removed in turn, the tests that should notice are run, and every file is restored. A test suite that passes either way proves nothing. Falsify.
Fast checks
Format, lint and type checks (checks.fast), cheapest first. They run before any test, so a slow test never runs only to be thrown away by a lint error. The gate and test speed.
Feature
How one part of the product works, step by step, with numbered rules (R-1 …) that stories cite as F-1/R-2 (F-1). Plan the work.
Follow-ups
The bugs, tasks and decisions a slice found along the way, created at close and listed in its close summary. Close and merge a slice.
Fresh eyes
A review by a new agent that did not write the work and carries nothing from the session that did — never the author's session, never a fork of it. Reviews with fresh eyes.
Front-matter
The key: value lines at the top of each document — id, title, state, owner, audience, blocked_by … — kept to a simple form the standard library can read. The plan is a folder tree.

G–M

Gate
spry gate: spry check, then the fast checks, then the affected tests, stopping at the first failure. A pass is stamped against the code, so it does not re-run while only documents change. gate --fast skips the tests. The gate and test speed.
Generated block
The part of a page between <!-- spry:… --> and <!-- /spry:… --> markers — progress tables, proof tables, index lines — written by spry index on the main branch only. Branches never change them, so they never conflict. Generated pages.
Glossary
Your project's spry/knowledge/glossary.md: one term per concept, what it means, and the words not to use for it. check fails on a banned word. Written for its reader.
Index (INDEX.md)
A generated list of a knowledge folder's items, one line each from their title and summary. An agent reads the index and opens one item, instead of reading everything. Knowledge and size.
Interview
How every planning skill works: a few questions at a time, with a drafted answer offered for you to confirm, each answer written into the document at once. Plan the work.
Line budget
The most lines a kind of file may have, set in the config and enforced by check. Knowledge and size.
Merge-check
spry merge-check: is a closed slice ready to merge? It blocks on a missing falsify row, a bare survivor, criteria changed with code without the owner's approval, a missing closed: date or PR number, or an unclean check. A criterion no test cites is a ! the merge asks you about. Tool commands.
Milestone
An outcome a person can check (M-1): why, done-when, scope, constraints. The top of the plan. Plan the work.
Mint
Where IDs are taken and slices claimed. local: the next number in this tree. main: taken on the main branch on the remote, so two sessions never take one number. Work as a team.
Must not
The part of a work order that lists, with links, the rules this slice could break — a decision, a security or performance rule. The review checks each still holds. Build a slice.
Mutation
How falsify removes a control: a guard made never true, a comparison's boundary flipped (>= to >), an error line deleted. Never a negation, which breaks the normal path too and gives a false catch. Falsify.

O–R

Open
The state of a slice being built: it has a work order, a conflict check, a branch and a draft pull request. Build a slice.
Planned
The state of a slice that exists but has not been opened: a summary, what it covers, and what it waits on. Split a story into slices.
Process files
The written rules every agent follows, copied into your project at spry/process/ so any agent reads the same ones. Yours to change, with /spry:process-change. Keep spry yours.
Proof
The generated table on a story showing what proves each criterion — a test's name, a QA check, or "not yet". Status is derived.
Proven
A criterion is proven by a test whose name contains its citation (S-1/AC-2), or by a pass as the latest row for it in the check log. A skipped test proves nothing, and a later fail row un-proves it, test or not. Status is derived.
Pull request (PR)
A request on GitHub to merge a branch into the main branch, where the change is reviewed. In spry, one slice is one pull request, and its body is copied from the slice file. Close and merge a slice.
Ready
The state of a plan item a person has agreed to, after its conflict check. A story goes ready only on a yes — its criteria are what "done" means. Where a person decides.
Rebase
Moving a branch's commits on top of the latest main branch, so it is tested against what it will merge into. slice-close rebases first, before the review and the gate. Close and merge a slice.
Related
The related list in front-matter, and spry related, which lists the candidates a conflict check must read. The conflict check.
Rule (feature rule)
A numbered rule in a feature, R-1, cited by stories as F-1/R-1 instead of being restated. Plan the work.

S–Z

Scenario
The steps QA follows by hand for one or more criteria, in a story's checks.md: type, where, whether it is ready to run, then numbered steps with what you should see. Checks for QA.
Skill
A command you type into your agent, like /spry:story. Skills are thin: each points at the process file that holds the procedure. Skills.
Skipped
A falsify result for a control that cannot run — it needs a clock or a network — recorded with a reason, for a person to accept at the merge. Falsify.
Slice
One reviewable change with one visible result: a work order, a branch, a pull request, covering one or more criteria of one story — or the work of a task or bug (SL-1). A slice is a file, not a folder. Split a story into slices.
Squash merge
Merging a pull request as one single commit. /spry:merge always squashes, with a commit message from merge-message that carries the slice's trailers. Close and merge a slice.
Stack profile
Per-language setup values — test commands, falsify runners, fast checks, how to keep spry/ out of the build — that setup copies into the config. TypeScript / Node, Python, and a generic one. Configuration.
Story
One thing a person does with the product, with its acceptance criteria (S-1). Write acceptance criteria.
Survived
A falsify result: the safeguard was removed and every test still passed — no test notices it. It needs a new test, or a written reason a person accepts at the merge. Falsify.
Task
Technical work no story asks for — set-up, upgrades, refactors — under the milestone or epic it serves (T-1). Does not count toward progress. Bugs and tasks.
Tone
Your personal override of the audience level, set with /spry:tone and kept in .spry/tone, never committed. Written for its reader.
Trailer
A Key: value line at the end of a commit message. spry's merge commit carries Slice:, Parent: and Covers: — and CI: when CI did not run — because a squash keeps nothing else. Close and merge a slice.
Unreliable
A falsify result when the tests could not give an answer: the baseline was red, or a run timed out. Fix that first. Falsify.
Vendor
Copying the process files and the tool into a project (spry vendor), so every agent reads the same rules and CI runs without any agent. Installation.
Wide
A falsify control whose criterion is cited by more than 20 test files. Named at the run, so you can list the files that matter. Falsify.
Work order
The first part of a slice file, written before any code: summary, covers, plan (one line per file), must not, tests, demo, conflict check. The pull request body is copied from it. Build a slice.
