Configuration

One file, spry/spry.config.json, holds everything about how spry runs in your project: the shape of the plan, the team, line budgets, and the commands that check and test your code. /spry:init or /spry:adopt writes it from your answers — you rarely edit it by hand.

It lives inside spry/

Not at the repository root. The tool finds the project by looking for spry/spry.config.json in the current folder and its parents.

The whole file

This is the template setup starts from. Values in <…> are filled in during the interview; a value still in <…> means that topic has no answer yet.

Version

KeyMeans
spryThe spry version vendored into this project.
spry_baselineThe last changelog entry (CH-n) this project considered. /spry:update offers every entry after it, then moves it forward.

Product and plan shape

KeyMeansDefault
productThe product's name. scrub treats it as a private word.—
levelsThe planning levels, biggest first. A small project may drop epic; features then sit straight under milestones.["milestone", "epic", "feature", "story"]
idsThe prefix for each type's IDs. IDs are flat counters per type — S-12, never M2.E3.S12 — so moving an item never renumbers it.M E F S SL T B D
planning.review"always": every new milestone, epic, feature, story, task and bug is read by a new agent before it goes ready, and you choose which findings to apply. "offer": you are asked once instead. A bug with replayable evidence skips it either way. See Planning."always"

Checks and tests

These say how the gate and CI check your code. Cheapest first: the fast checks run before any test.

KeyMeans
checks.fastFormat, lint and type checks, as {"name", "run"}, cheapest first. A check may also carry fix: the same tool in write mode, with {files} where the files go — for the formatter. spry.py step --commit runs each one on the step's files before the checks and says which files changed, so the check passes the first time. A check without fix stops the commit; leave it out to have a format failure stop it too.
checks.docsGlobs for files whose change never needs a test run. A branch that changed only these runs check alone. Default ["spry/**", "**/*.md"].
checks.generatedGlobs for files a command writes: a generated client, a schema dump, a package manager's lock file. Their lines are left out of a slice's size — the slices.steps.max_lines warning and pace's "lines changed" — and printed beside it as "n generated". Default: none.
checks.locktrue: only one gate or falsify run runs its commands at a time, across every worktree of this clone. A run that has to wait says who holds the lock and for how long, then goes on. For a machine where several sessions build side by side. Default false.
checks.lock_pathThe lock file. Default: a file in the system's temporary folder named after the clone's git directory. Give two clones the same path to order their runs too.
tests.matchGlobs that find test files — where check looks for criterion citations like S-1/AC-2 in test names.
tests.affectedA command that runs only the tests affected by the working tree. Used by gate — once at close, or whenever a test's answer is needed (gate --fast, run while building, runs no tests).
tests.retryThe affected tests again with no parallelism, run once when the first run failed on a timeout. Empty: never retry.
tests.alwaysOptional. Commands gate and CI run after the tests whenever code changed, whatever changed — tests that read the whole code tree, such as a banned-words or licence check. Each a string or {"name", "run"}.
tests.retry_whenOptional. A pattern in the output that marks a failure as a timeout. Default timed out|timeout|ETIMEDOUT.
tests.load_whenOptional. A pattern in the output that marks a failure as the machine's, not the code's, so a red gate runs again on the same code. Replaces the built-in list (Failed to start forks worker, EADDRINUSE, EMFILE, ENOMEM, ECONNREFUSED, ECONNRESET, ENOTFOUND, EAI_AGAIN, command not found); tests.retry_when still counts.
gate.keep_goingOptional. What the gate does after a failed check: fast (default) runs every fast check and then stops before the tests; all runs the tests too, so one run reports everything; off stops at the first failure.
tests.allEvery test, in parallel where the runner allows. CI runs it on the main branch and nightly; the agent never runs it as a routine step.
tests.junitWhere the runner writes JUnit XML, for spry tests --slowest.
tests.partsOptional. Parts of the suite that run differently — {"name", "run", "stack"}; stack: true means it needs local services. /spry:test-all runs them in order. Leave it out when tests.all is all there is.

Every command here runs in the system shell — sh on macOS and Linux, cmd.exe on Windows. If anyone on the team works on Windows, keep commands to what both understand: no VAR=value command prefix, and run project tools through the package manager (pnpm exec turbo, not a bare turbo), which finds them where the shell would not. A script in your project that reads these keys has to follow when you move a command between them.

Local services

KeyMeans
stack.runningExits 0 when the local services (database, queues) are up.
stack.upStarts them and waits until they are healthy.
stack.downStops them, keeping their data. /spry:test-all stops only what it started.

Exploratory testing

Used only by /spry:explore, and may stay <…> until its first run, which stops and asks.

KeyMeans
explore.envA file sourced in every shell, pointing ports and data away from your development instance.
explore.upStarts the isolated instance; --fresh resets its data, so a replay is a real replay.
explore.downStops it.
explore.fixtureCreates the starting data — two of everything that has a boundary (two organisations, two users with different roles), or the walk never tests isolation.

Falsify

KeyMeansDefault
falsify.parallelfalse, true, or a number of git worktrees to run controls in at once. Never touches your working tree. The baseline runs in each; one that is red while another is green is named once and left out.false
falsify.timeoutSeconds before a test run is stopped, with its whole process group. A timeout makes the control unreliable.600
falsify.shareExtra folders to link into each worktree beside the installed dependencies (node_modules, .venv, venv are linked already) — generated code tests import, for example.[]
falsify.keep_worktreesKeep the worktrees between runs, reset to HEAD with every untracked and ignored file removed at the start of each. A fresh worktree is cold — a virus scanner reads every file on its first run.true
falsify.setupA command run once in each slot — each worktree, or your tree when serial — before the baseline, with SPRY_FALSIFY_SLOT (1, 2, …) and SPRY_FALSIFY_SLOTS set: create and migrate that slot's database, say. Every test run sees the same two. A setup that fails stops the run. The older name of worktrees.setup, which wins when both are set.""
falsify.controlsWhich added lines falsify suggest drafts and merge-check requires. guards: a line that refuses, stops or decides. operators: also any line holding ||, && or a comparison, wherever it stands — the reach before 0.43.0.guards
falsify.runnersHow to run a list of test files. Each: match (test globs), command with {files} and the runner's fail-fast flag, optional cwd: "package" to run in the nearest package folder (a monorepo), "parallel": false for tests that cannot run side by side (a shared database, fixed ports), and failed — a pattern for the line the runner prints when a test failed, needed only when it is not pytest, vitest, jest, mocha, go, cargo, unittest, rspec or node --test, or a tool other than turbo or docker compose puts a prefix on each line. A run that fails without that line is unreliable, not caught.—

Pace

All optional. See See where the time goes.

KeyMeansDefault
pace.awayMinutes. A gap longer than this that is not a tool running counts as away and is left out of every number.30
pace.logsExtra folders of Claude Code session logs to read (globs), for a worktree outside the clone. The clone's own folder and its .claude/worktrees/ are read already.[]
pace.flagsWhen a slice is flagged: falsify_share, session_share (waiting on another session), lock_share (waiting for the check lock), lone_share (requests that called a tool and called only one) and merge_wait_share (waiting on you during the merge) as fractions, review_agents as a count.0.2, 0.2, 0.15, 0.9, 0.5, 3
pace.token_weightsWhat one token of each kind costs against one fresh input token: input, cache_read, cache_write_5m, cache_write_1h, output. A slice's spend is its tokens times these, so it is in input-token equivalents, not money. The defaults are the usual price ratios, not looked-up prices; set the ones that differ for your model.1, 0.1, 1.25, 2, 5
pace.bucketsChanged-line counts where one size bucket ends and the next starts. The page's By size table sets a slice against slices in its own bucket.[300, 700, 1300, 2500]

Agent hooks

Claude Code hooks that say at the moment of a mistake what check or merge-check would say later. Each is true or false; a missing key is off, so a project set up before 0.34.0 has none until it takes them. New projects start with all on. SPRY_HOOKS=off in the environment turns every one off for a session. See Agent hooks for what each does and how to add your own.

KeyMeans
hooks.sessionAt session start, resume, clear and compaction: tells the agent where the config and tool are, the slice this branch builds, your tone, and which hooks are on.
hooks.link_fieldsRefuses a hand edit of a slice's branch, pr or owner and names the link command that sets it.
hooks.cited_criteriaAsks you before a story's criterion changes or is dropped when a test already cites it.
hooks.check_editAfter an edit of a document, checks that one file and sends its errors back to the agent.
hooks.mergeRuns merge-check before gh pr merge of a slice's pull request, made from its branch, and refuses the merge if anything blocks it.
hooks.check_stopBefore the agent finishes with documents changed, runs check; on errors it goes back once to fix them, and the same documents are not checked again.
hooks.step_commitOn a slice built in steps, refuses a git commit of code and names spry.py step --commit, which runs the fast checks and marks the commit as its step. A --fixup, an amend, or a commit of staged documents goes through.
hooks.session_endWhen a session ends, gives back the worktree it claimed, so another session can take it at once. A /clear keeps it.

Worktrees and progress

All optional. Without a worktrees block, spry.py worktree says so and nothing else changes; the progress log and spry.py watch work either way. See Worktrees.

KeyMeansDefault
worktrees.dirWhere worktree new makes worktrees, from the main checkout..claude/worktrees
worktrees.home_branchThe branch a worktree rests on between slices, at the main branch's head. {index} and {name} are filled in.alt{index}
worktrees.maxHow many worktrees worktree new makes; each gets an index from 1 to this.4
worktrees.setupYour script, run once in a new worktree with SPRY_WORKTREE (its index) and SPRY_WORKTREE_NAME set: create its database, pick its ports, write its .env. Falsify slots run it too, with SPRY_FALSIFY_SLOT set as well, so one script isolates both.""
worktrees.shareFiles copied from the main checkout into a new worktree before the set-up — an .env.example, say.[]
worktrees.stale_afterHours after which a claim whose worktree wrote nothing can be taken by another session.12
progress.transcripts"claude-code": watch also reads each session's log, for what it is doing now — working, running a command, waiting on you — its context, its spend and the time since its last /clear.false
progress.quietMinutes without a progress line before watch marks a claimed worktree quiet.15
progress.keepLines the progress log keeps once it passes 256 KB.400

Slices and branches

KeyMeansDefault
slices.pickWhat /spry:slice-open with no ID does. offer: recommends the first ready slice, with two alternatives. ask: lists the first four and recommends none.offer
slices.design_reviewtrue: /spry:slice-open has one new agent read the finished work order before any code (/spry:slice-plan always does). A choice that is hard to undo and was not asked about is a Blocker, and becomes a question to you first. The counts go in the slice under Design review; merge-check warns when they are missing or a Blocker went unasked. Costs one agent and a few minutes a slice. See The design review.false
slices.fresh_contextTokens of context above which /spry:slice-open, /spry:slice-plan, /spry:slice-build and /spry:slice-close stop at their start, and /spry:merge before its ask, and ask you to /clear and run them again: every request would otherwise read the whole of what came before. The slice file carries everything the close needs. In a slice built in steps, step --commit says the same after a step's commit, so the next step starts in a fresh session. spry brief measures it from the session log. 0 turns it off; a value near the model's whole context window does too.150000
rigorThe level every slice works at unless a plan item says otherwise (rigor: in its front-matter covers it and everything under it; the nearest value wins). 1: every reading. 0: light — a slice that fits slices.light has no design review and one reviewer at close. Other values are refused: levels 2–5 are not built.1
slices.light.max_linesLines of code (counted as for slices.steps.max_lines) a slice at level 0 may change and stay light. Over it, the close reviews the slice in full and merge-check warns that its design was not read before the code.300
slices.light.neverGlobs. A slice whose plan names, or whose branch changes, a file under one of them is never light. Add what must always be read twice: auth, billing, a public API.["**/migrations/**", "**/*.sql"]
slices.steps.maxThe most steps one slice may hold; check refuses more. 1 makes every change its own slice and pull request. (slices.mode is gone: a config that still says split is read as max: 1, and check warns.)5
slices.steps.max_linesLines of code (documents and checks.generated files not counted) one slice should change. Over it, merge-check lists the size for you to accept at the merge. 0 turns it off.800
slices.steps.step_linesLines of code (counted as for max_lines) one step's commit should change — the size one reviewer reads. Over it, spry.py step --commit warns right after the commit, while the step can still be split, and merge-check lists it for you to accept at the merge. 0 turns it off.0
slices.steps.testsWhen true, spry.py step --commit runs the test files the step added or changed, after the fast checks, through falsify.runners. A failing one stops the commit and is named, so it is fixed in the step that wrote it and not at close. The affected tests still run once, at close.false
slices.steps.tests_skipGlobs for test files a step's commit does not run — the ones that need the local services up. The gate runs them at close.[]
main_branchThe repository's default branch — read from the repository at setup, never assumed.main
mintWhere IDs are taken and slices claimed. local: the next number in this tree; two branches can collide, and check --base names it before the merge. main: taken on the main branch on the remote, pushed at once — two sessions never take one number or one slice. Needs a main branch that accepts a direct commit of documents.local

Examples per stack

Setup fills the test and check commands from a stack profile. These are the profiles' values.

TypeScript / Node — Vitest

"checks": {
  "fast": [
    {"name": "format", "run": "prettier --check .",
     "fix": "prettier --write --ignore-unknown {files}"},
    {"name": "lint", "run": "eslint . --cache"},
    {"name": "types", "run": "tsc --noEmit"}
  ]
},
"tests": {
  "match": ["**/*.test.ts", "**/*.test.tsx"],
  "affected": "vitest run --changed origin/main",
  "retry": "vitest run --changed origin/main --no-file-parallelism",
  "all": "vitest run",
  "junit": "reports/junit.xml"
},
"falsify": {
  "runners": [
    {"match": ["**/*.test.ts", "**/*.test.tsx"],
     "command": "vitest run --bail 1 {files}"}
  ]
}

With Jest instead: jest --changedSince=origin/main for affected tests, --runInBand added for the retry, jest --maxWorkers=50% for all, and jest --bail {files} for falsify. In a Turborepo, turbo run test --filter=...[origin/main] runs only changed packages and their dependents; set "cwd": "package" on the falsify runners.

Python — pytest

"checks": {
  "fast": [
    {"name": "format", "run": "ruff format --check .", "fix": "ruff format ."},
    {"name": "lint", "run": "ruff check ."},
    {"name": "types", "run": "mypy ."}
  ]
},
"tests": {
  "match": ["**/test_*.py", "**/*_test.py"],
  "affected": "pytest --testmon",
  "retry": "pytest --lf -p no:xdist",
  "all": "pytest -n auto",
  "junit": "reports/junit.xml"
},
"falsify": {
  "runners": [
    {"match": ["**/test_*.py", "**/*_test.py"], "command": "pytest -x -q {files}"}
  ]
}

--testmon needs pytest-testmon and -n auto needs pytest-xdist.

Any other stack

The interview asks the developer for each value above. If the runner cannot run only affected tests, tests.affected runs the test files beside the changed source files instead, and AGENTS.md says so. Integration tests on a shared database get their own runner entry with "parallel": false.

A citation lives in the test's name

Whatever the stack, a test proves a criterion only when S-1/AC-2 is in the string that names it — a title, a docstring, a parametrize id. A citation in a comment or in code proves nothing. See Status is derived.
