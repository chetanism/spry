Configuration

One file, spry/spry.config.json, holds everything about how spry runs in your project: the shape of the plan, the team, line budgets, and the commands that check and test your code. /spry:init or /spry:adopt writes it from your answers — you rarely edit it by hand.

It lives inside spry/

Not at the repository root. The tool finds the project by looking for spry/spry.config.json in the current folder and its parents.

The whole file

This is the template setup starts from. Values in <…> are filled in during the interview; a value still in <…> means that topic has no answer yet.

Version

KeyMeans
spryThe spry version vendored into this project.
spry_baselineThe last changelog entry (CH-n) this project considered. /spry:update offers every entry after it, then moves it forward.

Product and plan shape

KeyMeansDefault
productThe product's name. scrub treats it as a private word.—
levelsThe planning levels, biggest first. A small project may drop epic; features then sit straight under milestones.["milestone", "epic", "feature", "story"]
idsThe prefix for each type's IDs. IDs are flat counters per type — S-12, never M2.E3.S12 — so moving an item never renumbers it.M E F S SL T B D

Team

"team": {
  "members": [
    {"name": "Asha", "github": "asha", "roles": ["product"]},
    {"name": "Ravi", "github": "ravi", "roles": ["developer"]},
    {"name": "Meera", "github": "meera", "roles": ["qa"]}
  ],
  "review": {"spry/plan/**": ["product"], "src/**": ["developer"]}
}
KeyMeans
team.membersName, GitHub handle and roles for each person. Empty means solo: nothing is routed for review, and approval is not required to merge.
team.reviewWhich roles review which paths. spry codeowners turns it into .github/CODEOWNERS. Planning skills open a pull request instead of committing to the main branch when a document falls under a rule here.

Budgets and knowledge

KeyMeansDefault
budgetsThe most lines a file matching each glob may have. spry check fails a file over budget; /spry:compact brings it back.AGENTS.md 150 · knowledge 120 · plan READMEs 150 · slice files 200
glossaryWhere the glossary is. check fails on its banned words anywhere in spry/ outside code, the glossary and conflict-check sections.spry/knowledge/glossary.md
always_checkKnowledge files every conflict check reads, whatever the document.security, performance, decisions index

Checks and tests

These say how the gate and CI check your code. Cheapest first: the fast checks run before any test.

KeyMeans
checks.fastFormat, lint and type checks, as {"name", "run"}, cheapest first.
checks.docsGlobs for files whose change never needs a test run. A branch that changed only these runs check alone. Default ["spry/**", "**/*.md"].
tests.matchGlobs that find test files — where check looks for criterion citations like S-1/AC-2 in test names.
tests.affectedA command that runs only the tests affected by the working tree. Used by gate — once at close, or whenever a test's answer is needed (gate --fast, run while building, runs no tests).
tests.retryThe affected tests again with no parallelism, run once when the first run failed on a timeout. Empty: never retry.
tests.alwaysOptional. Commands gate and CI run after the tests whenever code changed, whatever changed — tests that read the whole code tree, such as a banned-words or licence check. Each a string or {"name", "run"}.
tests.retry_whenOptional. A pattern in the output that marks a failure as a timeout. Default timed out|timeout|ETIMEDOUT.
tests.allEvery test, in parallel where the runner allows. CI runs it on the main branch and nightly; the agent never runs it as a routine step.
tests.junitWhere the runner writes JUnit XML, for spry tests --slowest.
tests.partsOptional. Parts of the suite that run differently — {"name", "run", "stack"}; stack: true means it needs local services. /spry:test-all runs them in order. Leave it out when tests.all is all there is.

Every command here runs in the system shell — sh on macOS and Linux, cmd.exe on Windows. If anyone on the team works on Windows, keep commands to what both understand: no VAR=value command prefix, and run project tools through the package manager (pnpm exec turbo, not a bare turbo), which finds them where the shell would not. A script in your project that reads these keys has to follow when you move a command between them.

Local services

KeyMeans
stack.runningExits 0 when the local services (database, queues) are up.
stack.upStarts them and waits until they are healthy.
stack.downStops them, keeping their data. /spry:test-all stops only what it started.

Exploratory testing

Used only by /spry:explore, and may stay <…> until its first run, which stops and asks.

KeyMeans
explore.envA file sourced in every shell, pointing ports and data away from your development instance.
explore.upStarts the isolated instance; --fresh resets its data, so a replay is a real replay.
explore.downStops it.
explore.fixtureCreates the starting data — two of everything that has a boundary (two organisations, two users with different roles), or the walk never tests isolation.

Falsify

KeyMeansDefault
falsify.parallelfalse, true, or a number of git worktrees to run controls in at once. Never touches your working tree.false
falsify.timeoutSeconds before a test run is stopped, with its whole process group. A timeout makes the control unreliable.600
falsify.shareExtra folders to link into each worktree beside the installed dependencies (node_modules, .venv, venv are linked already) — generated code tests import, for example.[]
falsify.keep_worktreesKeep the worktrees between runs, reset to HEAD with every untracked and ignored file removed at the start of each. A fresh worktree is cold — a virus scanner reads every file on its first run.true
falsify.setupA command run once in each slot — each worktree, or your tree when serial — before the baseline, with SPRY_FALSIFY_SLOT (1, 2, …) and SPRY_FALSIFY_SLOTS set: create and migrate that slot's database, say. Every test run sees the same two. A setup that fails stops the run.""
falsify.runnersHow to run a list of test files. Each: match (test globs), command with {files} and the runner's fail-fast flag, optional cwd: "package" to run in the nearest package folder (a monorepo), "parallel": false for tests that cannot run side by side (a shared database, fixed ports), and failed — a pattern for the line the runner prints when a test failed, needed only when it is not pytest, vitest, jest, mocha, go, cargo, unittest, rspec or node --test, or a tool other than turbo or docker compose puts a prefix on each line. A run that fails without that line is unreliable, not caught.—

Pace

All optional. See See where the time goes.

KeyMeansDefault
pace.awayMinutes. A gap longer than this that is not a tool running counts as away and is left out of every number.30
pace.logsExtra folders of Claude Code session logs to read (globs), for a worktree outside the clone. The clone's own folder and its .claude/worktrees/ are read already.[]
pace.flagsWhen a slice is flagged: falsify_share, session_share (waiting on another session) and merge_wait_share (waiting on you during the merge) as fractions, review_agents as a count.0.2, 0.2, 0.5, 3

Agent hooks

Claude Code hooks that say at the moment of a mistake what check or merge-check would say later. Each is true or false; a missing key is off, so a project set up before 0.34.0 has none until it takes them. New projects start with all on. SPRY_HOOKS=off in the environment turns every one off for a session. See Agent hooks for what each does and how to add your own.

KeyMeans
hooks.sessionAt session start, resume, clear and compaction: tells the agent where the config and tool are, the slice this branch builds, your tone, and which hooks are on.
hooks.link_fieldsRefuses a hand edit of a slice's branch, pr, issue or owner and names the link command that sets it.
hooks.cited_criteriaAsks you before a story's criterion changes or is dropped when a test already cites it.
hooks.check_editAfter an edit of a document, checks that one file and sends its errors back to the agent.
hooks.mergeRuns merge-check before gh pr merge of a slice's pull request, made from its branch, and refuses the merge if anything blocks it.
hooks.check_stopBefore the agent finishes with documents changed, runs check; on errors it goes back once to fix them, and the same documents are not checked again.

Slices and branches

KeyMeansDefault
slices.issuetrue: each slice gets a GitHub issue when it opens, from its work order, for people who follow issues rather than the repository. The close summary is posted on it; the merge closes it.false
slices.pickWhat /spry:slice-open with no ID does. offer: recommends the first ready slice, with two alternatives. ask: lists the first four and recommends none.offer
main_branchThe repository's default branch — read from the repository at setup, never assumed.main
mintWhere IDs are taken and slices claimed. local: the next number in this tree; two branches can collide, and check --base names it before the merge. main: taken on the main branch on the remote, pushed at once — two sessions never take one number or one slice. Needs a main branch that accepts a direct commit of documents.local

Examples per stack

Setup fills the test and check commands from a stack profile. These are the profiles' values.

TypeScript / Node — Vitest

"checks": {
  "fast": [
    {"name": "format", "run": "prettier --check ."},
    {"name": "lint", "run": "eslint . --cache"},
    {"name": "types", "run": "tsc --noEmit"}
  ]
},
"tests": {
  "match": ["**/*.test.ts", "**/*.test.tsx"],
  "affected": "vitest run --changed origin/main",
  "retry": "vitest run --changed origin/main --no-file-parallelism",
  "all": "vitest run",
  "junit": "reports/junit.xml"
},
"falsify": {
  "runners": [
    {"match": ["**/*.test.ts", "**/*.test.tsx"],
     "command": "vitest run --bail 1 {files}"}
  ]
}

With Jest instead: jest --changedSince=origin/main for affected tests, --runInBand added for the retry, jest --maxWorkers=50% for all, and jest --bail {files} for falsify. In a Turborepo, turbo run test --filter=...[origin/main] runs only changed packages and their dependents; set "cwd": "package" on the falsify runners.

Python — pytest

"checks": {
  "fast": [
    {"name": "format", "run": "ruff format --check ."},
    {"name": "lint", "run": "ruff check ."},
    {"name": "types", "run": "mypy ."}
  ]
},
"tests": {
  "match": ["**/test_*.py", "**/*_test.py"],
  "affected": "pytest --testmon",
  "retry": "pytest --lf -p no:xdist",
  "all": "pytest -n auto",
  "junit": "reports/junit.xml"
},
"falsify": {
  "runners": [
    {"match": ["**/test_*.py", "**/*_test.py"], "command": "pytest -x -q {files}"}
  ]
}

--testmon needs pytest-testmon and -n auto needs pytest-xdist.

Any other stack

The interview asks the developer for each value above. If the runner cannot run only affected tests, tests.affected runs the test files beside the changed source files instead, and AGENTS.md says so. Integration tests on a shared database get their own runner entry with "parallel": false.

A citation lives in the test's name

Whatever the stack, a test proves a criterion only when S-1/AC-2 is in the string that names it — a title, a docstring, a parametrize id. A citation in a comment or in code proves nothing. See Status is derived.
